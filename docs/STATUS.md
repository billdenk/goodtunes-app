## 1. Recent changes

### Done and live
- Press-specific print spec fields + checks (2026-08-11, MRP guide parity): each press can now record its own print standards — press-level defaults on a new "Print rules." section of the Catalog Specs surface (bleed minimum + recommended, safety margin, standard + bitmap/line-art PPI floors, grayscale-required and official-Pantone-only toggles, placed-image format rule, general + center-label advisories, accepted-formats note, and downloadable .joboptions / preflight-profile reference files), with per-component overrides in the template-specs editor. The completed-artwork check dialog now measures bleed from the PDF's own trim/bleed boxes against that press's numbers (fail below minimum, warn below recommended), runs an advisory edge-band raster heuristic ("outer bleed band appears empty" — warn only, never fail), applies a second PPI floor to 1-bit line-art images, verifies grayscale-only ink on B/W-flagged pieces, flags spot colors whose names don't look like official Pantone inks, warns on PNG/GIF-provenance placed images, and lists un-machine-checkable rules (safety area, label knockout) as info-tier advisory rows in the press's own wording. Verdicts cite the press by name ("Memphis Record Pressing requires ≥0.125" bleed; 0.25" recommended"). MRP's guide values are seeded; presses with no values entered keep exactly today's behavior. Uploaders see the press's accepted-formats note + reference downloads on the Completed Art panel. Design brief for the entry surfaces published at docs/press-print-spec-design-brief.md (Ruby mocks in parallel).
- Catalog › Specs page (handoff/press-specs, 2026-08-11): presses now publish "the numbers artists press against" — per-format audio master-file rules (Vinyl: formats/bit depth/sample rate/side lengths per size+speed/cutting guidance; CD: Red Book masters, max length, ISRC, pregap; Cassette: shell side lengths) plus one set of art rules (resolution floors, bleed/safety geometry, color mode/PMS/formats/fonts). Handoff design rendered verbatim (dark canon body; Audio|Art pill left, Save right — gray-outline disabled until something changes, then the page's one blue pill). Press portal gets a flat "Specs" rail item under Catalog; super admins see the same page via a quiet section pull-down next to the Catalog heading on the press page (GoodTunes Packages / White Label "Soon" / GoodDeed Certificates / Specs, deep-linkable `?section=`). Values start at the handoff defaults and persist per press (`manufacturers.audio_specs`/`art_specs` jsonb, migrated dev + prod); edits are press-editor gated (Staff read-only), strict server validation.
- CD disc preview silkscreen bands (2026-08-11): the CD render in the catalog build page now paints picked silkscreen spot colors as concentric bands (first pick outermost, even radius shares between hub and edge), dark inks get a subtle edge ring so they read on the charcoal canvas, and the collapsed Silkscreen summary row's disc chip shows the same bands.
- Press payouts via Stripe Connect (2026-08-10): super admins can now pay presses/plants in-system. New System → "Vendor payees" page lists every press with a truthful onboarding status (Not invited → Invited → Onboarding → Active, advancing off the account.updated webhook with a live-retrieve fallback while pending), and emails/re-sends each press its Stripe Express onboarding link. From an album's manufacturing ledger a super admin clicks Pay vendor, picks an Active press, enters the amount, and confirms an explicit dialog naming vendor + amount + project; the Stripe transfer fires immediately (idempotent, double-submit-safe) and the transfer ID is shown. Insufficient-balance errors surface as the clean Stripe message, never a raw 500. Every transfer — success or failure — is recorded per project (vendor, amount, date, transfer ID, initiating admin, linked inbound paid steps) in a money-in/money-out view plus an attempt audit log. Ledger reuses payout_earmarks (sourceKind vendor_payout) + a new vendor_transfer_attempts table; model write-up in docs/press-payout-ledger.md. All routes are super-admin only (partners 403).
- Manufacturing invoices payable by pushed bank transfer (2026-08-10): on a due Shopify+ ledger step the artist now sees "Pay by bank transfer" (primary, no fee) showing Stripe's virtual account details in-app (bank, routing, account number, exact amount, reference, one-tap copy per field, print/save-PDF) plus a "Card +fee" fallback with the 2.9%+30¢ card fee disclosed before confirming. ACH debit removed from this flow. New "Awaiting transfer" state flips to Paid via Stripe webhooks only; short transfers within $15 (configurable) auto-close; larger partials show received vs remaining and a second transfer to the same account completes them; payer details are logged; operators see leftover Stripe cash balances (overpayments) in the Payments tab. Artist gets an email confirmation when funds land. LIVE Stripe account enabled 2026-08-10 (Dashboard wizard; live smoke PI returned full wire instructions) and the production webhook endpoint now subscribes to all bank-transfer events — see docs/bank-transfer-payments.md.

## 2. Super-admin press Catalog tab — current behavior
- Each press's detail page has six tabs: Dashboard, Overview, People, Albums, Catalog, Analytics.
- The Catalog tab shows a "Catalog format" segmented control with three pills: Vinyl, CD, Cassette.
- Vinyl is the only live format. It defaults to 12" LP (or the first offered size) and shows: vinyl size tabs, pressing types/tiers, run-size price ladders (140g/180g books), color swatches, print/audio spec templates, turnaround, branding (center-label logo + background), and reorder/hide controls. Saving is explicit ("Edited · Save catalog").
- Handoff-default state (2026-08-10): the page opens on 12" LP with the **Black** type pre-picked and Classic Black selected, so the hero shows the black record in the sleeve. The Black type carries its own three colors (Classic Black / Midnight / Jet) — empty Black tiers were seeded idempotently on dev + prod via post-merge. "Pick a type" collapses to a one-line summary once a type is picked (small disc chip + type name + "Type · n colors" + a blue Change link); Change re-expands the grid, and picking a type collapses it again.
- CD and Cassette pills are live. Each opens its handoff build page (per-format header copy "On disc." / "On tape.", sticky product render on the left — jewel case/sleeve with the peeking disc, or shell photo with the printed piece — and the choice column on the right). Selections are live previews; the persisted parts are custom silkscreen spot inks (CD), the run price ladder, and the turnaround override. Staff see it read-only like vinyl.
- The jacket stage renders a black printed jacket with the press's logo, sticky and top-anchored on desktop.

## 3. Press-facing catalog & artist builder — current behavior
- The press portal (Dashboard, Clients, Projects, Acquisition, Catalog, Settings, Referrals) renders the exact same Catalog component as super-admin, so press users see what operators see.
- Press Owners/Admins can edit everything (formats, prices, colors, branding, templates, GoodDeed printing ladder); press Staff get a read-only view with a notice.
- An "Add your vinyl" colors sub-view handles disc color swatch setup.
- The artist-facing package builder ("Design your package. See what it earns.") pulls from the press's vinyl catalog — sticky jacket preview on the left, decisions and live earnings math on the right. If a press hasn't published a vinyl catalog, artists see a friendly empty state.
- CD and cassette: the press-side catalog build pages are live (same component for press portal and super-admin). The artist-facing package builder still only offers vinyl — CD/cassette builder flow not designed yet.
