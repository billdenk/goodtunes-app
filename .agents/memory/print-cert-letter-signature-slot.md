---
name: Letter print-cert band — decoupled top-flow + bottom lock-up
description: How the GoodDeed Letter print-cert headline/signature/credit/footnote share the navy band without colliding on long names/titles, plus the artist avatar
---

The GoodDeed print-cert mockup engine (`_CertPrint.tsx`) renders the **Letter** band as TWO decoupled absolute blocks (NOT one flex column):

1. **Top-flow block** (`top: headlineYRel`): headline div, then the signature squiggle `<img SIG>` (`marginTop: px(sigGap)`). Flows from the top so the squiggle always sits directly under a 1- or 2-line headline.
2. **Bottom lock-up block** (`bottom: px(pad + footBottomGap)`): the William credit div + provenance footnote div as ONE unit. Always bottom-anchored, so it ALWAYS keeps its breathing space off the orange border and its last line stays on the QR caption baseline — regardless of how many lines the headline wraps to.

Because the two blocks are independent, when a long recipient/title wraps the headline to 2 lines the squiggle just drops down toward the William credit instead of shoving the footnote past the border. The long-name tile (`longLockup`, see below) tunes this so the squiggle just **touches the top of William** rather than striking through it.

**Why this replaced the earlier single flex column:** the prior version put headline + signature + footnote in ONE absolute flex column (footnote `marginTop:auto`). That bottom-anchored the footnote only *when there was room*; a 2-line headline ate the slack and pushed the footnote (and its QR-caption baseline alignment) downward. Decoupling guarantees the bottom lock-up never moves.

**A4 band — also two decoupled blocks now (provenance demoted to a bottom footnote).** A4 used to be ONE vertically-centred flex column (title → headline → provenance paragraph → `makeSignatureBlock(2)`), with provenance mid-stack at 7.5pt in reading order. Bill chose to restructure it (Option 1) so it reads like the Letter: (1) an **upper centred block** (`top: safeTopRel`, `height: safeBottomRel - safeTopRel - a4ProvReserve`, `justifyContent:center`) holding `titleRow` + headline + `makeSignatureBlock` (squiggle + William credit; see credit-tuck note below); (2) a **bottom-anchored provenance footnote** (`bottom: px(a4ProvBottom)`, `fontSize: 7`, indented to the body text column at `leftColLeftRel + avatarSize + 10`). `a4ProvBottom = qrCaptionBottomRel` lands the footnote's last-line baseline on the QR "GoodDeed®" caption baseline (verified by row-profile: both bottoms at the same pixel). `a4ProvReserve` (44) is the bottom band height kept clear so the centred upper block can't overlap the footnote — raise it if William ever crowds the footnote. At 7pt the provenance string wraps to 2 lines (was 3 at 7.5pt). This is the reverse of reading order (signature now sits ABOVE the provenance) — Bill explicitly accepted that trade for the bottom-baseline alignment.

**The William credit tucks UP under the squiggle via a NEGATIVE `makeSignatureBlock(creditMt)` — because the SIG png has ~3.8pt of transparent bottom padding.** `will-signature.png` is 464×132 with content bbox 450×109+7+7, so 16px (≈12%) of transparent padding sits below the visible ink; at the rendered `width: px(110)` that's ~3.8pt. A `creditMt` of +2 therefore leaves a ~6pt VISIBLE gap (William box-top is +2 below the png bottom, which is itself 3.8pt below the last ink). To match the Letter's tucked credit, A4 uses `makeSignatureBlock(-4)` (≈ zero visible gap; gap ≈ `creditMt + 4.3`pt). **Don't reason about the gap from the png's box edge — subtract the transparent padding first.** Verify by eye against `LetterBorderThin.tsx`, not by row-profiling the squiggle (a vertical strip usually misses the lowest ink, which is an off-centre flourish).

**Horizontal QR-plane boundary is already enforced (don't re-clamp).** Both the A4 body headline and the provenance footnote live in containers bounded by `leftColRightRel = qrColLeftRel - 14`, i.e. they wrap 14pt LEFT of the QR column's vertical plane. Long recipient names (stress-tested with "Alexandria Montgomery-Worthington") wrap to a new line before reaching the QR — text never crosses the QR's imaginary vertical line. No extra width clamp is needed.

**Artist avatar (all tiles, Letter + A4).** The round avatar in `titleRow` shows the ARTIST, not the album art. `const ARTIST` is the default; `CertPrint`/`CertStage` accept an optional `artistPhoto?: string` prop, and `avatarSrc = artistPhoto ?? ARTIST` feeds the avatar `<img>`. The mockup's default artist face lives at `artifacts/mockup-sandbox/public/images/artist-fernando-perdomo.png`. Bill's rule: use the REAL person photo from the DB, not a crop of the album image. Source it from `people.photo_url` (a `/objects/uploads/<id>.png` object) — fetch via the running app's object endpoint and drop it in the mockup's `public/images/` (canvas iframes can't load main-app `/objects` paths). **Downscale to ~512px before saving** — the raw object can be ~2.5MB/1200px and a multi-MB file intermittently fails to paint in the tiny circle (and shows blank in screenshots); 512px renders reliably. Fernando Perdomo's record is prod-only (`people.name='Fernando Perdomo'`), absent from dev/task DBs.

**Signature stacking — squiggle IN FRONT of the William credit (normal Letter tile).** The headline+signature top-flow block and the William+footnote bottom lock-up are separate absolutely-positioned siblings; in DOM order the credit block paints last, so by default the "William…" text punches through the squiggle ink where they meet. The top-flow block gets `zIndex: lowerCreditLockup || longLockup ? 1 : undefined` so the squiggle reads as one continuous stroke over the name on BOTH the normal and long tiles. **The prop is named `lowerCreditLockup`** (was `creditUnderSig`): it (1) drops `footBottomGap` 9→6 to lower the credit+footnote+QR-caption lock-up together so the squiggle clears William, and (2) gates that z-index lift. It does NOT move William into the top group (that approach overlapped the footnote — abandoned).

**Long-name tile — `longLockup` prop (set on `LetterBorderThinLong.tsx`).** A 2-line headline pushes the squiggle a full line lower, so the whole bottom region needs to ride lower as a unit. `longLockup` combines two moves: (1) a negative `footBottomGap` drops the credit+footnote+QR-caption lock-up so the cluster hugs the band bottom (footnote + caption stay coupled via `qrCaptionBottomRel`, so their baseline lock survives any drop); (2) the same z-index lift as the normal tile so the squiggle paints in front of William. Net effect Bill wanted: the whole bottom cluster (squiggle → William → footnote + QR/GoodDeed) sits ~10px lower hugging the band. `pad`=14, so `footBottomGap`=-5 leaves the cluster about as far down as it can go before crowding the orange border. Never set both `lowerCreditLockup` and `longLockup` on the same tile.

**`sigGap` is the ONLY lever on the squiggle↔William overlap — and it must MATCH on both Letter tiles, NOT move in tandem with `footBottomGap`.** Earlier note claimed you had to drop `sigGap` in lockstep with the long tile's `footBottomGap` to keep the squiggle touching William; that was wrong and made the long squiggle sit ~3pt too low (striking through William). **Why:** the squiggle is top-anchored off the headline; the long tile's 2-line headline drops it ~11pt (9.5pt × 1.15 line). William is bottom-anchored and the long tile's `footBottomGap` (6 on the non-long `lowerCreditLockup` → −5 here = 11pt) drops William ~11pt too. Those two ~11pt drops **cancel**, so the squiggle↔William gap is left governed by `sigGap` alone. Therefore the long tile must use the SAME `sigGap` as the non-long tile (currently `const sigGap = -2;` unconditionally) for the squiggle to meet "William…" at the same spot on both. **How to apply:** if the squiggle↔William overlap looks different between the long and non-long tiles, change `sigGap` only — do NOT couple it to `footBottomGap`. More-negative tucks the squiggle UP under the headline.

**Caption baseline is NOT the same as footnote-block bottom — the QR offset is tile-specific.** `qrCaptionBottomRel = pad + footBottomGap - (longLockup ? 3 : 5)`. The shared `-5` (normal Letter + A4) must stay; the footnote's 6pt last line and the 7pt "GoodDeed®" caption sit in differently-anchored boxes, so coupling them with the same offset leaves the caption mis-set on the long tile. Long-tile tuning history (qrCaptionBottomRel value → measured caption-bottom vs footnote-baseline): `4`=too low (below), `12`=~3px above, `9`=~1px above (Bill still read the 7pt caption as floating high), `6` (offset `3`)=caption bottom ~1px below footnote baseline = the bottom of "GoodDeed" sits ON the footnote's second-line baseline, which is what Bill approved. **Lesson:** moving footnote and caption "in lockstep" only preserves an *existing* alignment — if they were misaligned, lockstep keeps them misaligned; the per-tile offset is what actually aligns the two baselines, and it must be tuned per tile because box anchoring + font size differ. **Verify by pixel row-profile, not eyeball:** `magick "$f" -crop WxH+X+Y +repage -colorspace Gray -resize 1x{H}! txt:-` collapses a strip to one column of per-row gray values; the lowest bright row in the footnote strip vs the caption strip gives the two baselines to the pixel. Eyeballing a drawn red line was too lenient and led to wrongly declaring alignment twice.

**Canvas iframe serves STALE after a mockup edit — a `?v=` on the `url` field alone isn't reliable; delete+recreate the shape.** The board's gooddeed-print tiles embed bare `/__mockup/preview/.../LetterBorderThinLong` URLs (no cache-bust). After editing the component the operator's long-lived iframe kept showing the OLD render even after they closed/reopened the canvas — HMR doesn't reach that frame and the headless screenshot tool (fresh load each time) showed the NEW build, so the two disagreed and I kept insisting it was fixed. Fix that actually worked: restart the `mockup-sandbox` preview workflow for a clean build, then `applyCanvasActions` **delete** the iframe shape and **create** it again with the SAME `shapeId`, same x/y/w/h, and a `?v=${Date.now()}` URL. A brand-new DOM element forces a fresh fetch.

**Footnote breaks AFTER the second "GoodDeed®" (Letter only).** The provenance copy says "this GoodDeed®" twice and the QR caption is also "GoodDeed®". A4 renders the copy as one naturally-wrapping string (`provenance`). The Letter footnote uses a separate `provenanceFootnote` (two `<div>`s) whose break is placed AFTER the *second* "GoodDeed®" so both mentions stay on the upper line and the bottom line ends on "…possessed ownership of this good." Bill's rule: break after the second GoodDeed, never the first.

**How to apply:** any time you adjust Letter band placement, stress-test with a long recipient AND long title (`LetterBorderThinLong.tsx`) AND the normal baseline (`LetterBorderThin.tsx`). Smallest type in the band is 6pt (footnote provenance); trim words rather than shrink below that. This is a MOCKUP only — the shipped PDF in `server/goodDeedPrintTemplate.ts` is intentionally NOT edited by canvas work.

**Per-tile sample override:** `CertPrint`/`CertStage` accept an optional `sample?: Partial<CertSample>` merged over the default `SAMPLE` as `S`; pass it from a tile to render alternate artist/title/recipient/num without touching the shared default.
