---
name: In-tree native iOS Capacitor plugin
description: How native-only iOS capabilities (e.g. system volume) are added as an in-tree Swift plugin + gated in the shared web codebase.
---

Native-only iOS capabilities live as **in-tree Capacitor plugins committed to
`ios/App/App/*.swift`**, NOT npm packages.

**Why:** the GoodTunes apps are a thin Capacitor wrap of the same web app; a
one-off native bridge (system volume, etc.) doesn't warrant a published plugin.
`cap sync` only copies npm-package plugins — it will NOT pick up a `.swift` file
dropped into `ios/App`, and it won't delete it either.

**How to apply:**
- Write the Swift plugin as `CAPPlugin, CAPBridgedPlugin` with `@objc(<Name>Plugin)`,
  declaring `identifier` / `jsName` / `pluginMethods`.
- **Capacitor 6 does NOT auto-register in-tree app-target plugins** (an earlier
  version of this doc claimed it did — FALSE). There is NO Obj-C runtime scan in
  `@capacitor/ios` 6.x: `CapacitorBridge.registerPlugins()` loads ONLY 4 hardcoded
  built-ins + the classes listed in `packageClassList` (capacitor.config.json,
  generated by `cap sync` from **npm** packages). A `.swift` plugin in the App
  target is never in that list, so it silently never registers
  (`Capacitor.isPluginAvailable` false, every call no-ops). This hid for months:
  the two plugins with JS fallbacks (SecureKeyStore→IndexedDB, SystemVolume hidden
  on web iOS) masked it; NowPlaying has no fallback, which finally exposed it.
- **Register each in-tree plugin EXPLICITLY.** `ios/App/App/MainViewController.swift`
  subclasses `CAPBridgeViewController` and calls
  `bridge?.registerPluginInstance(<Name>Plugin())` for every in-tree plugin inside
  `override open func capacitorDidLoad()` (invoked in `loadView()` BEFORE the web
  page loads, so the injected JS proxy WKUserScript is ready). Use
  `registerPluginInstance`, NOT `registerPluginType` (the latter is a no-op while
  `autoRegisterPlugins` is on — the default). `Main.storyboard`'s initial VC MUST
  point at this subclass (`customClass="MainViewController" customModule="App"
  customModuleProvider="target"`) or the override never runs and you're back to
  the 4+npm list. **Adding a new in-tree plugin = add one `registerPluginInstance`
  line here too**, not just the pbxproj entries.
- It MUST also be added to the Xcode target by hand — edit `ios/App/App.xcodeproj/project.pbxproj`
  in 4 places: a `PBXBuildFile` entry, a `PBXFileReference` entry, the `App`
  `PBXGroup` children, and the `PBXSourcesBuildPhase` files list (mirror how
  `AppDelegate.swift` appears in all four). Use fresh unique 24-hex IDs.
- **Verify on-device provenance:** the NowPlaying plugin exposes `getBuildInfo()`
  returning the Info.plist `GTGitCommit` (stamped by the Codemagic archive step
  from `CM_COMMIT`) + version/build; the operator Now Playing diagnostic overlay
  reads it back, so you can confirm exactly which commit produced the installed
  binary. The remote-origin shell otherwise makes "is this build stale?"
  unanswerable on-device — a non-empty commit readback ALSO proves registration
  landed (getBuildInfo only works if the plugin registered).
- JS side: `registerPlugin<T>("<jsName>")` in a `client/src/lib/native*.ts`
  wrapper, fully guarded so it's a no-op on web.
- Gate the UI on `isNativeIOS` (show native-only) vs `isWebIOS` (hide on Safari)
  from `client/src/lib/platform.ts` — never raw `Capacitor.isNativePlatform()`.
- None of this compiles/tests in the Replit container (no Cocoapods/Xcode);
  correctness is verified only when a Mac cuts the build per `docs/native-builds.md`.

**System volume specifically:** read via `AVAudioSession.outputVolume`; SET only
by nudging a hidden off-screen `MPVolumeView`'s embedded `UISlider`
(`slider.value = x; slider.sendActions(for: .valueChanged)`) — there is no
public setter. Live hardware-button changes come from KVO on `outputVolume`.
